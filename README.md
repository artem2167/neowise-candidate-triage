# Neowise — помощник для входящих заявок

Менеджер вводит заявку, получает тему и черновик ответа, проверяет его и сам решает, что отправить клиенту. При сбое AI страница предлагает разобрать заявку вручную и убирает прежний черновик.

## Запуск

Нужен Node.js 20 или новее. Зависимостей, установки пакетов и API-ключей нет.

```sh
node server.mjs
```

Откройте <http://127.0.0.1:3000>. Остановить сервер можно через `Ctrl+C`.

Для другого порта в PowerShell:

```powershell
$env:PORT = "3001"
node server.mjs
```

## Исполнимые тесты

Из корня проекта, без отдельного запуска сервера:

```sh
node --test
```

Тесты API поднимают настоящий HTTP-сервер на свободном локальном порту и проверяют:

- HTTP 400 для битого JSON, отсутствующего, пустого и нестрокового `text`; AI при этом не вызывается.
- Все три допустимые темы и непустой черновик при успехе.
- Все пять сбоев исходного имитатора и неверные структуры ответа AI.
- Ограничение ожидания 300 мс, отмену запроса и восстановление после таймаута, включая провайдера, игнорирующего отмену.
- Отсутствие непроверенных дополнительных полей AI в ответе API.

Тесты страницы исполняют её настоящий обработчик в `node:vm` с небольшим заменителем DOM и сети. Они проверяют отображение результата, очистку старого черновика при сбоях, пустой ввод и повторные запросы. Это проверка поведения страницы без внешних библиотек; визуальную проверку выполняют в браузере.

## Контракт API и проверка AI

`POST /api/triage`, JSON с полем `text` — непустой после `trim()` строкой.

| Ситуация | HTTP | JSON |
| --- | --- | --- |
| Неверный ввод или битый JSON | 400 | `{"status":"invalid_input"}` |
| Корректный ответ AI | 200 | `{"status":"ready","topic":"delivery","draft":"…"}` |
| Таймаут, ошибка AI или неверный результат | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

Проверка результата AI находится в `handleTriage` в `server.mjs`, после `JSON.parse` и до формирования `ready`. Принимается только объект с темой `delivery`, `pricing` или `other` и строковым черновиком, непустым после `trim()`. Ответ формируется из проверенных полей; остальные поля модели не передаются клиенту.

Ожидание AI ограничено 300 мс через `Promise.race`. По таймауту передаётся сигнал отмены `AbortController`; ограничение работает и при игнорировании сигнала провайдером. Таймер очищается при любом исходе. Выданный `mock-ai.mjs` не изменён.

На странице неверный ввод объясняется менеджеру. При сбое старые тема и черновик очищаются, текст заявки остаётся доступным для ручного разбора и повторной попытки. Данные AI выводятся через `textContent`.

## Ручная проверка

1. Отправьте «Когда доставка?» — появятся тема «Доставка» и черновик.
2. После успешной заявки отправьте по очереди `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Для каждого сбоя должен появиться ручной разбор без старого черновика и темы.
3. Отправьте обычную заявку снова — результат должен восстановиться.
4. Отправьте пустую строку и пробелы — появится просьба ввести текст.

## Польза менеджеру

Помощник сокращает время первичного разбора заявки и подготовки ответа; пользу можно измерить медианным временем от открытия заявки до одобренного менеджером черновика, сравнив работу с помощником и без него при одинаковом качестве ответов.

## Использование AI

При доработке использован OpenAI Codex (GPT-6). После генерации изменений отдельно выполнены `node --test` (62 проверки, все пройдены на Node.js 24.16.0) и браузерный прогон: успех → каждый из пяти сбоев → повторная попытка → пустой ввод. Проверяемый коммит указан в PR.
